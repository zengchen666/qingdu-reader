## 二、验收怎么做的

```
四本真书 → RagCorpusProbe（真实检索 + 真实段落切分）→ _rag-corpus.json
        → rag_live_check.py（复用服务真实的 select/validate）→ 逐例判定
```

**刻意不用假文本**：真书里一段可能上千字、章内段落数极不均匀。
切分在真书上的真实形态正是最容易出问题的地方，用造出来的文本验等于没验。

### 验收问题必须按书配对

第一版四本书**共用同一组问题**，结果「药老」在《武动乾坤》里 0 命中
—— 药老是《斗破苍穹》的人物。那不是检索 bug，是**素材设计缺陷**：
跨书共用问题会制造大量假阴性，让人误以为召回坏了。

最终每组三类问题，对应三种召回行为：

| 类型 | 例（配对后） | 预期 |
|---|---|---|
| 单个专有名词 | 云岚宗 / 药老 / 叶修 / 荣耀 / 元尊 | 命中 |
| 跨书错配（对照组） | 药老@武动乾坤、洛尘@元尊 | 召不回 |
| 纯语义问题 | 「萧炎是怎么变强的」等 3 例 | **召不回 → 诚实说不知道** |

## 三、🔴 验收发现的 bug：召回排序缺一环

### 现象

| 问题 | 候选池 | 含答案的段 | 送进上下文的 8 段含词 | 模型回答 |
|---|---|---|---|---|
| 全职高手 / 叶修 | 156 段 | **66 段** | **0 段** | 「原文里没有提到叶修」 |
| 斗破苍穹 / 药老 | 105 段 | **25 段** | **0 段** | 「原文里没有提到药老」 |

**模型没有幻觉 —— 它说的是真话。** 送进上下文的 8 段里确实一段都不含「叶修」。
防幻觉机制工作正常；**是召回侧把答案漏掉了**。

### 根因

`select()` 第一版只做「去重 + 章节打散 + 截断」，**完全依赖传入顺序**。
而轻读传的是「FTS5 命中章 → 该章**全部**段落 → 按章排列」，
**不是**按段落命中次数排列。一章 60 段里命中词可能落在第 39 段，
而打散取「每章**前** 2 段」—— 含答案的段永远进不了上下文。

> ⚠️ 这与 v0.2「零假阳性」结论**不冲突**：那验的是「命中的都准」（查准率），
> 这次发现的是「该命的没全被选上」（查全率）。**两个方向要分别验证才看得出来。**

### 修法

`select()` 增加 `question`，先按关键词命中数**稳定重排**，再分组打散。
**重排必须在打散之前** —— 打散取「每组前 N 段」，先排好才取得到相关的段。

### 附带发现：`_query_terms` 静默退化

第一版只是「删标点」，于是 `text.count("叶修是怎么退役的")` **恒为 0**，
打分对长句完全失效，**且不报任何错**。改成 n-gram 滑窗
（`CjkTokenizer` 同一思路），无意义组合按片段集合整体过滤。

### 效果（同一批数据）

| 书 / 问题 | 候选 | 修前含词 | 修后含词 |
|---|---|---|---|
| 全职高手 / 叶修 | 156 | 0 | **8** |
| 斗破苍穹 / 药老 | 105 | 0 | **7** |
| 斗破苍穹 / 云岚宗 | 70 | 1 | **7** |
| 全职高手 / 荣耀 | 80 | 2 | **8** |
| 元尊 / 元尊 | 74 | 1 | 2 |
| 武动乾坤 / 云岚宗 | 147 | 0 | 1 |

模型回答随之改变：

* 叶修：「原文里没有提到叶修」 → 「叶修是陈果网吧的新员工，被使唤搬新键盘…」
* 药老：「原文里没有提到药老」 → 「药老自称药老，说来历先不告诉萧炎…」

## 五、诚实的边界

**这次验收证明不了的**（不要夸大）：

1. **引用校验只能拦形式错误，拦不住内容错位。**
   模型若引用了有效编号 `[3]`，但那句话的内容其实来自 `[5]`，
   机器无从发现。引用机制的价值是**让错误可被发现**（用户点开能核对），
   不是保证不出错。
2. **语义类问题 0 召回。** 「萧炎是怎么变强的」这类问题关键词召回无解，
   v0.4 明确不处理（诚实返回"没找到"）。**这是 v0.5 向量召回的动机**。
3. **样本量小**：6 例真实调用，不足以做统计意义上的结论。
4. **只测了 DeepSeek 一家、一个问题形态**（短问句）。
   换模型 / 换问法需要重跑。
5. **界面未做**：轻读侧还没接线，引用能不能点、跳转对不对，
   要等 A 步完成后人工目视。

## 六、复现方式


## 七、给 A 步的三条硬要求

1. **轻读必须传 `chapterIndex` / `paragraphIndex`**，不能只传章号 ——
   引用要精确到"第几章第几段"才可点击。
2. **轻读不要自己再排序**。它传「按章排列的该章全部段落」即可，
   排序是 Python 侧的责任（两处排序 = 两处真理 = 迟早不一致）。
3. **切片段要按 `ChapterBlock.Paragraph`**，不要自己按空行再切一遍 ——
   段落是 `qingdu-common` 的既有概念，轻读已经切好了。
