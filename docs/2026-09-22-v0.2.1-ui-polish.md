## 一、这一版要解决的真实问题

| # | 用户提出的原话 | 真问题 |
|---|---|---|
| 1 | 每一章的末尾可以加一个上一章和下一章按钮 | 读完一章想继续时，手要离开正文去左侧目录里点下一章 |
| 2 | 可以将左侧章节栏收起，让文章位于屏幕中间 | 目录栏占 24% 宽度，宽屏上正文偏在右边；但目录还是想留着的，只是"不总想看" |
| 3 | 主题可以再多加两个…护眼有点太绿 | 护眼主题的底色饱和度过高，长时间看反而累；可选项只有四套 |
| 4 | 弹窗有点太素，并且会挡住其他一些地方 | ① 弹窗完全没被主题覆盖；② 设置是模态的，调的时候看不见正文 |

第 4 条的两半是**两个独立问题**，而且第 ① 半是真正的 bug：

`base.css` 里当时有 `.settings-dialog`，但**一条 `.dialog-pane` 规则都没有**。
`Alert` 的根节点样式类是 `.dialog-pane`，于是所有确认框 / 错误框 / 关于框
都落回 JavaFX 默认的 Modena 外观 —— 一个惨白的框。

这件事**只在浅色主题下看得出来**：夜间主题顺带覆盖了 `-fx-base` 这类内置根变量，
把 Modena 一起带深了，看起来居然还算协调。所以问题被掩盖了很久。

## 二、四个改动分别怎么做

### 1. 章末翻章（`ChapterNavBar`）

三栏等宽布局：`[← 上一章 / 标题]  第 12 / 1474 章  [下一章 → / 标题]`。

- **放在正文流里，跟着正文滚动**，而不是固定在窗口底部 —— 读到章末时它就在眼前，
  正常阅读时它在视口之外、不占屏幕。
- **首章 / 末章的按钮置灰而不是隐藏**。隐藏会让中间的「第 N / M 章」左右横跳
  （少一个按钮就少一份宽度），置灰则位置稳定，还顺带说明了"这是边界、功能没坏"。
- **按钮下面带一小截目标章节标题**：章节标题本身有信息量的书（带卷名的那种），
  用户想先看一眼再去。
- 快捷键 `Alt + ← / →`（新开的「阅读」菜单里也有一份）。

**唯一会算错的地方是下标**：`index - 1` 在第一章会得到 -1，直接拿去 `List.get` 就是越界崩溃。
所以目标下标由两个静态方法算，返回 -1 表示"没有"，由 6 个单元测试钉住
（含"只有一章""下标等于总章数""负数下标"这些换书瞬间可能出现的中间态）。

**为什么翻章条不能做进 `ChapterRenderer`？** 因为设置窗口的预览区复用了那个渲染器 ——
做进去的话，预览里会冒出两个翻章按钮，点了还会真的跳章。

### 2. 目录栏可收起

`F9` 或书籍信息条右侧的开关。

**不能只写 `setDividerPositions(0)`。** `TabPane` 的最小宽度是由三个标签
（目录 / 书签 / 搜索）撑出来的，收起时它会把分隔条顶在那个最小值上、根本到不了 0，
屏幕上留下一条约 100px 宽的"贴着标签文字的窄条"，比不收起还难看。
所以要把 `minWidth` 和 `prefWidth` 一起压到 0，展开时还原成"按内容计算"。

**刻意不动 `maxWidth`**：这样分隔条仍留在最左边，想用鼠标拖回来的用户拖得动 ——
开关和拖拽两条路都通。同时因为 `minWidth` 还在（拖动时并未被清零），
**鼠标是拖不到 0 的**，于是"位置为 0"只可能是程序设的，状态判断不会打架。

收起的宽度**会记住**：展开时还回用户自己拖到的位置，而不是写死回 0.24。

`-qd-panel-bg` 与 `-qd-content-bg` 的区别在这里体现得最明显：目录栏一收，
正文在整块区域里居中（版心本来就是按"一行 34 字"算死宽度、靠对齐居中的）。

### 3. 主题扩到六套

新增 **雾蓝**、**墨黑**；**护眼改成灰绿**（原先把饱和度调得太高）。

| 主题 | 定位 | 面板 / 纸面 |
|---|---|---|
| 日间 | 默认，最中性 | `#eef1f4` / `#ffffff` |
| 护眼 | 灰绿，去掉原来的"绿得发亮" | `#dfe4db` / `#e9ede6` |
| 雾蓝 | 冷调浅色，长时间看不发黄 | `#e4e9ee` / `#eef1f4` |
| 羊皮纸 | 暖黄纸感 | 已存在 |
| 夜间 | 深色，第一套 | 已存在 |
| 墨黑 | 更纯的黑，对比更强 | `#16161a` / `#0d0d0f` |

两个必须记住的点：

1. **面板色和纸面色在每个主题里都必须不同**，否则侧栏和正文连成一片、看不出边界。
2. **`-qd-on-accent` 不能写死成白色**（这一版新引入的变量）。
   浅色主题的强调色是**深**的，白字没问题；但墨黑主题为了让强调色在深底上看得见
   用的是**亮**蓝，白字压上去直接糊成一片。所以它必须逐主题给值。

加主题只有两步（`Theme` 枚举 + `theme-*.css`），但"忘了建文件"和
"少写一个变量"都是**不报错的错**。为此加了 `ThemeCssCompletenessTest`：
把 CSS 当纯文本解析，按"`-qd-xxx` 后面跟不跟冒号"区分定义与引用，验证
① 六个主题都能解析到文件；② 每个主题都定义了 `base.css` 兜底用到的全部变量；
③ 主题里没有 `base.css` 不认识的变量；④ `base.css` 自己没引用未定义的变量。
**测试不需要图形环境**，所以 CI 上跑得起来。

### 4. 弹窗层统一 + 设置改独立窗口

**统一弹窗外观**（`base.css` 新增一大段）：`.dialog-pane` 及其标题区 / 内容区 / 按钮栏、
`.context-menu` 及其菜单项 / 选中态 / 禁用态 / 分隔线。全部走 `-qd-*` 变量，
所以六个主题自动统一。

顺带一个必须自己做的判断：**默认按钮（回车触发的那一个）用强调色**。
Modena 默认只给它一圈蓝描边，在羊皮纸 / 雾蓝 / 护眼下会明显跑调。

**设置从模态 `Dialog` 改成非模态 `Stage`**，拆成两个类：

| 类 | 职责 |
|---|---|
| `SettingsPane` | 面板本体：控件 + 预览 + 改动回调 |
| `SettingsWindow` | 窗口：非模态、位置、换肤、生命周期 |

**改动立刻生效，没有确定 / 取消。** 这是非模态的自然结果：窗口不挡正文，
用户可以一边拖滑块、一边看主窗口重排，一轮就调好；而"取消"的语义在这里
价值不大 —— 调字号是可逆的试错，不是提交一份表单。

非模态的代价是 `Dialog` 原本代劳的三件事要自己做：

1. **换肤**：`Stage` 有自己的 `Scene`，不继承主窗口的样式表。
   且主题从菜单切换时要**同步回面板**（面板内部持有一份设置副本，
   不同步的话它还带着旧主题，用户接着拖一下滑块就会把旧主题一起"应用"回来 ——
   表现为"改了主题又自己跳回去"）。
2. **跟着主窗口退出**：JavaFX 只在**最后一个**窗口关闭时退出。不主动收掉设置窗口，
   用户点了叉会发现进程还在任务栏里。
3. **首次出场别飞到屏幕正中**：它是辅助窗口，应该贴着主窗口。

窗口只在第一次点开时创建，之后复用同一实例：位置和大小被窗口管理器记住，
也省下重复枚举系统字体列表的开销（`Font.getFamilies()` 在 Windows 上要解析几百项）。

## 五、已知风险 / 未验证项

1. **ComboBox 弹出层的主题继承**。JavaFX 的 `ComboBox` 下拉是独立的弹出窗口，
   它的 `Scene` 是否会继承主场景的样式表，取决于 JavaFX 实现细节。
   如果验收 C 的最后一项挂了，修法是给 `fontBox` 的弹出列表单独挂样式表
   —— 但**先看现象再动手**，不要预先加复杂度。
2. **滑块轨道的对比度**。`base.css` 里给 `.settings-pane .slider .track` 用了
   `-qd-panel-subtle`，在墨黑主题下与窗口底色 `#0d0d0f` 的差别可能偏小。
   验收时留意一下，太弱就把轨道改成 `-qd-border` 或给描边加粗。
3. **目录栏收起后的分隔条**。收起时刻意保留了分隔条（为了能用鼠标拖回来），
   它会在左边缘留一条约 6px 的竖线，这是**有意为之**，不是渲染错误。
   如果看起来太像"坏了"，可以把 `maxWidth` 也清零、完全依赖开关和 `F9`。
4. **收起状态不进数据库**。目前是**会话内记忆**（收起 → 换书 → 仍收起），
   重启程序会回到展开。没有做持久化，是因为要往 `setting` 表加键 ——
   这一版的范围刻意压在"界面打磨"，不动存储层的键集合。
   真要做的话，`ReaderSettings` 加一个 `sidebarCollapsed` 字段即可，
   `from()`/`toMap()` 的逐项兜底机制能直接兼容老数据。
