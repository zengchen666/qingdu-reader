## 三、发现的问题（按影响排序）

### P0-1 章节名里的 `！？` 被当成正文（**误杀 251 章**）

`ChapterTitleMatcher.containsSentenceEnding()` 只要整行**含**句末标点就拒绝。但真实小说里大量章节名本身带感叹号/问号：

```
第007章  休！          ← 斗破苍穹
第009章  药老！        ← 斗破苍穹
第050章  帮？          ← 斗破苍穹
第三十八章 输出是什么？    ← 全职高手
第三十九章地元境！      ← 武动乾坤
第三百五十七章 突破，实境中期！ ← 元尊
```

被拒之后，这些章并入前一章 —— 于是同时出现**三个症状**：候选数变少、序号跳号、章节超长。三项数据互相印证：

| 文件 | 含句末标点被拒 | 序号缺号 |
|---|---|---|
| 斗破苍穹 | 153 | 158 |
| 全职高手 | 51 | 59 |
| 元尊 | 34 | 94 |
| 武动乾坤 | 13 | — |

**修法**：把"含句末标点"从**整行含**收紧为两条精确规则 ——
- `。` 继续全禁（章节名几乎不用句号，正文句子几乎都有）；
- `！？…` **允许出现在标题末尾**（后面没有其他非空白字符），若出现在中间且后面还有 ≥3 个字符则拒绝。

这样 `第007章 休！` 通过，`第二章 他到底想说什么！` 这类正文句子也会通过形态校验 —— **但会被第三重"序号单调"拦住**（正文引述的章号不可能恰好接在正确的序号位置上）。也就是说：这道防线的职责应该从"形态"挪到"位置"。相应地，`ChapterTitleMatcherTest` 里 `"第二章 他到底想说什么！"` 断言"必须拒绝"这条要改成在**流水线层面**验证被序号校验拦下。

### P0-2 章节标题与作者感言拼在同一行（**漏切 974 章，武动乾坤只剩 295 章**）

下载站抓取产物会把作者感言和章节标题合并成一行，标题在**行尾**，整行远超 40 字，被形态校验当正文毙掉：

```
行 329 | 　　（早...麻烦各位兄弟姐妹，看完更新的时候，麻烦投一张推荐票吧，谢谢第七章淬体第四重
行 330 | 　　第七章
行 368 | 　　（求收藏，求推荐票，麻烦大家了，谢谢第八章冲突
```

《武动乾坤》全书 1333 章，文件里有 **432 个行首标题 + 1328 个行内标题**，而行首形态只有 401 个能通过校验 —— 这就是它只剩 295 章的原因（`序号跳号 138 处、累计缺号 1033` 完全对得上）。

**修法**：新增"行内标题切分"。
- 一行被拒时，从行尾向前 42 字符内找 `第`，取其到行尾的子串重走 `ChapterTitleMatcher`；
- 通过则把该行**切成两段**：前缀（感言）归上一章，标题子串作为新候选，其 `startOffset = 行起始偏移 + 前缀字节长度`；
- 两段过滤防误收：① 前缀必须以句末标点 / `~` / `！` 结尾；② 序号必须落在已解析序列的"空档"里。
- 探针里已经实现并验证过这个判定：四本书里 986 条候选，其中 985 条落到序号空档（真漏切），误报极少。

### P1-1 虚词黑名单过宽（**误杀 15 条**）

`FORBIDDEN_TITLE_PREFIX = "的了着过吧呢吗啊嘛哦呀是"` 把 `过` / `是` / `了` 也当成正文特征，但它们是常见章节名首字：

```
第四百九十章 过三关      第八十一章 是福是祸
第六百三十九章 过时      第三百二十七章 是个高手
第九百三十章 过关        第七百五十五章 了不起的新人
第一百四十六章 过分理智   第一千一百七十四章 过路招呼
```

**修法**：把 `的` / `了` / `着` / `过` / `是` 移出黑名单，只保留真正的语气助词（`吧/呢/吗/啊/嘛/哦/呀`）。`的` 可保留（"的…"开头的章节名极罕见）。字数统计里 `了` 只有 1 例，属边缘情况。

### P1-2 引号开头的标题被拒（**误杀 1 条**）

```
第二十九章 “首杀队”    ← 全职高手
```

`PUNCTUATION_PREFIX` 里含成对引号。**修法**：把 `“”‘’「」『』` 从"禁止开头"里去掉，只保留句读类标点（`，。、；：！？…—～·`）。

### P2-1 卷标题独立成章（目录里出现空条目）

《全职高手》有 3 个卷标题被切成章节，长度 21~23 字节，在目录里就是三个几乎空白的条目：

```
#1    第一卷 高手被驱逐   (23 B)
#88   第二卷 被退役了     (21 B)
#1017 第三卷 我回来了     (21 B)
```

**修法**：两种取向 —— (a) `Kind.VOLUME` 不再产出 `Chapter`，只作为分组元数据（`Chapter.volumeTitle`），目录里渲染成可折叠的卷头；(b) 保留但 UI 折叠。推荐 (a)，语义更干净。

### P3-1 作者名尾部残留杂符（真 bug，中文文件名下同样复现）

```
author = 天蚕土豆』     ← 源自文件头 『武动乾坤/作者:天蚕土豆』
```

`AUTHOR_SEPARATORS` 只含开括号和常见分隔符，没含**闭**引号/闭括号。**修法**：把 `』」”’"'>）】]}` 也加进分隔符集合。

### P3-2 书名清洗还能再进一步（打磨项，非缺陷）

真实文件名提取结果：
- `《元尊》` → `《元尊》`（书名号没剥掉）
- `《全职高手》（精校版全本）作者蝴蝶蓝` → `《全职高手》作者蝴蝶蓝`（残留 `作者xxx`）

**修法**：`cleanFileName` 里补两步 —— 剥掉首尾书名号 `《》『』`；正则去掉 `作者[:：]?xxx` 尾巴。

### 6.1 新增根因 P0-3：序号校验的「级联误杀」（原报告没发现）

按顺序修完 P0-1 / P1 / P0-2 之后重跑语料，《武动乾坤》只从 295 章回到 **936 章**
（真书 1333 章）。这个数字不对劲，于是把 Java 侧的判定规则**原样搬到 Python 复算**，
得到与 Java **逐项吻合**的结果（1685 候选 / 935 保留 / 750 拒），才定位到真正的病灶：

```
行13758  inline  序号=248   ← 最后一个被保留的候选
行13807  inline  序号=449   ← 源文件混进来的错位高序号，被"接受"了
行13857  inline  序号=250   ← 250 <= 449，被判成"正文引述" → 拒
…  之后 249~448 共 227 个候选**全部连坐被拒**（保留项中 249..448 = 0 个）
```

原第三重校验是**贪心规则**：维护"上一个序号"，谁不大于它谁就被当作正文引述丢掉。
问题在于它**没有全局视野** —— 一个错位的高序号一旦被接受，它后面**所有**更小的
合法序号会被一路误杀，直到序号重新超过它为止。**一个错位值毁掉 200 章。**

**修法**：把贪心规则换成**分段 + 段内最长严格递增子序列**。
1. 先按「出现卷标题」或「序号重新回到 1」把候选切成若干**段** —— 这一步是为了隔离
   "每卷从第一章重新数"的书，否则求递增子序列会把后面每一卷都当倒退而丢光；
2. 再在每段内求**最长严格递增子序列**（耐心排序 O(n log n) + 前驱回溯），
   子序列之外的候选才丢弃。

错位序号无法成为最长递增链的一部分，于是被自然排除，而它后面那 200 章完整保留。
同一序号重复出现时保留**最早**一条 —— 真书里"标题贴两遍"（行尾黏一次、独立成行一次）
非常常见，留最早的能让上一章正文干净地结束在标题之前。

### 6.3 与原判断的两处偏差（如实记录）

1. **P0-2 的防误收手段改了。** 原计划用"序号必须落在已解析序列的空档里"，
   实际改用「**标题内不能含逗号 / 顿号 / 分号**」+ 第三重序号对齐兜底。
   理由：前者要在切分过程中边走边查已解析序列，代价高且和第三重职责重叠；
   后者是就地判据，实测精确挡住了唯一一类误收（`第一回合的交手中，便是败得如此的凄惨？`
   这类句子尾巴一定带逗号），且实现更简单。
   另外原写的"回溯窗口 42 字符"实际取的是 `MAX_LINE_LENGTH`（40），与形态校验同源。
2. **`…` 仍按全禁处理。** 原建议 `！？…` 一并允许收尾，实际只放开了 `！？!?`，
   省略号留在"任何位置否决"的集合里 —— 省略号收尾的章节名本就少见，而正文省略号极多，
   放开它的收益远小于风险。虚词表最终移出 `了/过/是`，保留 `的/着`。

### 6.4 仍然遗留（判定为**源文件数据问题**，不是代码缺陷）

1. **错字章号**：《武动乾坤》源文件把 861 章写成 `第三百六十一章`（漏个"八"），
   相邻的 863 也写成 `第三百六十三章`。这类错误只能靠"上下文推测原稿意图"来还原，
   不是序号规则能解决的，也不该由阅读器去猜。
2. **尾部残卷**：文件末尾 `第1333章` 是黏在正文段落末尾的孤岛，其后约 1 MB
   再没有任何可识别标题（包含作者完结感言与站点声明）。这一块仍是一个未切分的超长章节。
